# 章末断点之后，什么时候需要找回旧问答？

GPT-6.2-sol 在 24 个新留出章的配对实测中，12 问的版本追问答全数从 78/96 到 73/96，24 问从 172/204 到 170/204。补回策略的单问输入费分别为现有检索的 1.17 倍和 0.92 倍。未达到预先登记的全部启用门槛，补回保留为可选功能。

## 策略与留出集

对已定位章节的话题保留整章、章末缓存断点和每一次更正的原话。带明确版本的问题继续使用最近两组。遇到相对版本追问时，沿同话题往回找，保留最近一次明确选择原文或工作稿的问答，并按发生顺序补回其后缺失的用户选版指令。中间版本的模型答案容易带入旧值，继续留在历史库。遇到范围冲突、选版链不连续或整组补回超过字符预算，沿用原装配。

《十日终焉》前 200 万字符中排除了本机 1,286 份旧跟踪覆盖的 465 章，再抽取 4 个开发章、24 个留出章和 28 个新干扰章。每两个目标章为一组。四套系统收到相同的提问和更正，同组 12 问与 24 问的前 12 问相同，系统事先不知道何时结束。每轮都点明回到哪章，相对版本题不直接给出版本。每个系统独立生成真实答案，后续追问沿用自身历史。开发集 288 问，留出集 1,728 问，另有 56 次共享的入库读取请求。[固定方案](protocol.json) · [章节清单](../../bench/anchor_split.json)

三个章末策略共 1,296 次留出请求，发送前逐条核对当前整章、断点位置、当时该话题全部更正原话、每条问答的顺序与内容。所有账单回执核对了输入、缓存读写、输出和请求 ID。判分沿用上一轮的保守规则，要求两项都答全。被标记的回答由 MiMo v2.6 Flash 隐去实验组别复核，分歧或额外细节再查整章。规则与复核未达成一致的题计零分。这个指标也会因漏答、额外断言或题目歧义而下降。

## 哪些题实际补了历史

| 长度 | 线索状态 | 最近两组答全 | 按需补回答全 | 从错变对 / 从对变错 |

12 问中补回 48/144 问，平均每次补 109 个字符，发生在第 9、10、11、12 问。24 问中补回 108/288 问，平均每次补 131 个字符，此外还有第 14、15、17、21、24 问。例如第 17 问，窗口已有第 14、15 问，这时还要补第 3 问的完整问答和第 6、7、9、12 问的选版指令。第 21 问只需补第 16 问的一组问答。以上触发轮次来自实际出站装配。原来线索齐全的追问没有额外补回，但各系统已积累各自的回答，仍会有得分波动。

同章同题配对，按 12 组双话题对话整体重采样 10,000 次，版本追问答全率差值的 95% 区间为 12 问 -11.5 至 +0.0 个百分点，24 问 -4.9 至 +2.9 个百分点。相对最近两组，按需补回的单问输入费在 12 问变化 +4.7%、24 问变化 +8.1%。每答全一题总成本分别变化 +6.4% 和 +6.2%。

逐题回看，24 问中确实触发补回的 108 道追问有 5 道由错转对、7 道由对转错。第 629 章的两道回退都给出了当前工作稿的两项值，人物和数量的输出顺序发生了变化。第 651 章两道题都找到了最新的两个值，却把人物和物品对应反了。缺了最初那条明确选版的指令，最近两组里仍可能留有足以识别版本的上一条回答。整组恢复旧问答，还可能把原来问法中的字段顺序带回来。

## 使用与复核

运行时版本已在本次公开分支的 `b5fa8c1` 提交留档。协议里的 parent 是实验所在本机分支的基线编号。

在支持显式章末缓存断点的聊天后端配置 `HR_WHOLE_CHAPTER_HISTORY=1`、`HR_CHAPTER_QA_WINDOW=2` 和 `HR_CHAPTER_EDITION_ANCHOR=1` 可试用。实验总字符预算为 5,500。线上触发只读消息和当前话题，不接触测试的轮号、预计时长和答案标签。

原始问答、锁定题库和完整账本位于本机私有归档。持有相同小说和该归档时，可用以下命令离线复核。要核对旧轮错例，`bench/diagnose_edition.py` 接收上一轮的解封目录、小说路径和输出路径。对外汇总不包含小说全文、模型凭证或用户对话。

```sh
python bench/report_version_anchor.py PRIVATE_RUN BOOK anchor-test recomputed.json
python -m pytest -q tests
```
